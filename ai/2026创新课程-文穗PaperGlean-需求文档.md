## 一、项目理念

科研人员每天面对预印本平台、会议与期刊官网、学者个人主页等高度分散的论文信息源，检索与筛选成本高；而现成的论文推送与推荐服务普遍是黑盒——推荐理由不可见、用户反馈无法沉淀为可追溯的兴趣演化、数据与归档托管在第三方，使用者既无法检验推荐是否可信，也难以纠正它。

本项目的理念是**把学术情报的主动权还给研究者本人**：做一个个人自持、推荐理由完全可解释、兴趣演化全程可审计的论文推荐与归档工作台。

系统的核心价值不在于更聪明的算法，而在于“可解释”与“可审计”——

- 每一条推荐都能回答“为什么推荐给我”；
- 每一次兴趣变化都能回答“何时、因何、改了什么”。

四条价值主张：

| 价值 | 说明 |
|------|------|
| 个人化 | 基于用户真实研究兴趣，而非热门趋势 |
| 可解释 | 每条推荐都有依据，每个权重变化都有记录 |
| 可审计 | 兴趣画像与演化过程对用户完全透明，可校验、可纠正 |
| 本地主权 | 数据只属于使用者本人，可版本化管理、可随时完整迁出 |

## 二、关键需求

| 编号 | 需求 | 说明 |
|------|------|------|
| R1 | 多源聚合 | 统一汇集论文预印本、会议与期刊动态、指定学者的最新成果（含论文、视频、技术报告、学术报告等形态），并按用户兴趣自动筛选与去重 |
| R2 | 可解释推荐 | 每条推荐必须给出明确的**命中依据与权重**（命中了哪些兴趣点、各占多少权重），不得出现无理由的“你可能喜欢”；兴趣画像须以人类可读、可手工修改的形式呈现，用户可随时审计与校正 |
| R3 | 反馈闭环 | 用户对推荐结果的兴趣度与好奇度评分须被完整记录，并影响其后的推荐结果，使兴趣画像持续演化；演化过程须全程留痕、可追溯、可回放 |
| R4 | 归档与摘要 | 支持把选定论文的元数据与全文归档到本地，并按日生成可离线阅读的摘要汇总 |
| R5 | 数据主权 | 兴趣画像、反馈记录、归档内容与订阅名单等全部数据均保存在用户本地，可版本化管理、可离线使用、可随时完整迁出，不依赖任何云端账号 |
| R6 | 轻量交付 | 须在个人电脑上以最小依赖直接运行，并同时提供命令行与图形化两种使用方式，不引入重型基础设施 |

---

## 三、非功能约束

1. **本地优先**：数据主权归用户，全部内容保存在用户本机。
2. **失败显式**：采集环节失败时必须显式降级并明确提示，**不得静默返回“无新作”**。
3. **部署规模**：面向单用户本地部署，不设并发与多租户要求。

---

## 四、范围外（Non-Goals）

- 多用户 / 社交 / 评论 / 协作共享
- 云托管与账号体系
- 通用引文图谱探索、通用 AI 文献问答与系统综述工具
- 改变归档目录结构与文件命名规则
