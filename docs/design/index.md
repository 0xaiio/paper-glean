> Paper-Glean Web 界面的**目标形态与交互契约**。本文档是「设计意图」的唯一入口：
> 它规定界面**应该长什么样、怎么用**，并把每一条能力标注为「已实现 / 规划中 / 差异」。

## 1. 设计方向

| 维度 | 决定 |
|------|------|
| 定位 | **本地 Web 工作台**（desktop-first 三栏），非营销页；首屏即信息 |
| 调性 | **学术专业 · 中性克制 · 工具理性**（data-dense / utilitarian / dark-first / restrained） |
| 设计系统 | **Linear 基因**（暗色优先、高信息密度、键盘原生、1px 描边替代阴影） |
| 品牌色 | `--accent #3B82F6` 仅用于**非文本**（链接/选中/焦点环/描边）；**实心按钮与白字填充一律用 `--accent-fill #2563EB`**（白字 5.17:1，满足 WCAG AA）；不引入第二品牌色 |
| 默认主题 | **暗色**（跟随系统为规划项） |

选型理由与完整令牌见 [设计系统](design-system.md) 与 [ADR-004](../product/decisions/adr-004-design-system.md)。

## 2. 信息架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│  Paper-Glean    [Digest] [Profile] [Archive]        ⌘K(规划)  ☀/☾  ▾密度   │
├──────────────┬──────────────────────────────────────┬────────────────────┤
│ 日期          │  卡片流（虚拟滚动）                    │  详情面板（sticky）  │
│ 类别          │  ┌────────────────────────────────┐  │  标题 / 全作者      │
│ 命中类型       │  │▎Hermes: Prefix Consensus  [cs.DC]│  │  类别 / ★🧐 得分     │
│  ★ / 🧐 / 其余 │  │  Dahlia Malkhi et al.           │  │  全文摘要           │
│ 搜索          │  │  Leader-based BFT protocols…    │  │  为什么推荐(逐条)    │
│ 密度          │  │  为什么推荐: 分布式计算与共识 w=3 │  │  Open PDF / arXiv   │
│              │  │  我★ ▮▮▮▯▯  ★3    [⬇][arXiv][id] │  │  打分 pips          │
│              │  └────────────────────────────────┘  │                    │
│              │  …                                   │                    │
└──────────────┴──────────────────────────────────────┴────────────────────┘
                     Digest 流（/digest，主工作台）
```

| 页面 | 路由 | 职责 |
|------|------|------|
| **Digest 流** | `/digest` | 主工作台：筛选 → 逐张浏览 → 打分 → 下载；右栏看详情与「为什么推荐」 |
| **兴趣画像** | `/profile` | 把 `interests.md` 可视化为可读画像：★/🧐 条目 + keywords + 权重 + 来源 |
| **归档库** | `/archive` | 已下载 PDF 的清单与定位 |

**布局断点**（令牌见设计系统 §5/§8）：≥1280 三栏全展开 → 1024–1280 三栏收窄 →
768–1024 右栏转抽屉 → <768 单列 + 全屏抽屉。

## 3. 交互契约

### 3.1 键盘映射

| 键 | 行为 | 状态 |
|----|------|------|
| `j` / `↓` | 选中下一张卡（滚动居中 + 加载详情） | ✅ 已实现 |
| `k` / `↑` | 选中上一张卡 | ✅ 已实现 |
| `1`–`5` | 对当前选中卡打 ★（我给的评分） | ✅ 已实现 |
| `Shift+1`–`5` | 对当前选中卡打 🧐 | ✅ 已实现 |
| `d` | 下载当前卡的 PDF | ✅ 已实现（无回执 → 待补） |
| `o` | 新标签打开 arXiv 摘要页 | ✅ 已实现 |
| `/` | 聚焦搜索框 | ✅ 已实现 |
| `Esc` | 输入框失焦 / 关闭抽屉 | ✅ 已实现 |
| `s` 收藏 · `n` 笔记 · `⌘K` 命令面板 | — | 📝 规划 |

**硬性约定**：键盘操作只作用于**当前选中卡**；焦点在 `INPUT/TEXTAREA/SELECT` 时除
`Esc` 外不拦截；`j/k` 到边界**钳制不循环**。

### 3.2 打分即生效

- 无二次确认、无弹窗；打分后**卡片角标即时更新**并显示权重变动（如 `分布式计算与共识 3→4`）。
- 规则：评分 ≥4 → 命中条目权重 **+1**；≤2 → **−1**；写 `feedback.jsonl`（append-only，可回放撤销）。
- 卡片需落一个「**我给的** ★N/🧐N」状态位，与「**系统算的**命中徽标」在三重维度上区分：

| 维度 | 命中得分（系统算的） | 我的评分（我给的） |
|------|--------------------|------------------|
| 形态 | 顶部**实心 pill 徽标** | 底部**5 格 pips 分段控件** |
| 颜色 | 通道满饱和实心（amber/sky） | 仅填充已选格 |
| 交互 | 只读（hover 显命中条目） | 可点 / 可键盘打分 |

> 一句话记忆：**顶部实心徽标 = 系统的判断；底部条状控件 = 我的判断。**

### 3.3 双通道语义（不可混同）

★ 兴趣点 = **amber**；🧐 扩展点 = **sky 青蓝**（刻意与品牌 azure 拉开色相）。
两通道不仅靠色相区分，还带独立字形与位置冗余编码，色盲可辨（详见设计系统 §2.4/§2.5）。

### 3.4 主题与密度

- **默认暗色**，顶栏切换浅色，切换平滑过渡（≤240ms）。
- 阅读密度可切「舒适 / 紧凑」（紧凑档压缩卡片内距与摘要行数）。
- 全部动效尊重 `prefers-reduced-motion`。

## 4. 内容模型：一张卡承载什么

| 区块 | 字段 | 约束 |
|------|------|------|
| 标题 | `title` | ≤2 行，超出省略；点击跳 `abs_url` |
| 类别徽标 | `primary` | 等宽小号，如 `cs.DC` |
| 命中徽标 | `hits_star`/`hits_expand` + `score_*` | 实心 pill，含等宽得分数字；无命中不渲染 |
| 作者 | `authors` | ≤4 人 + ` et al.`，单行 |
| 摘要节选 | `abstract` | ≤2 行（约 280 字截断） |
| **为什么推荐** | 命中条目名 + `w=权重` | **仅在命中时显示；这是产品的灵魂，不可省略** |
| 操作行 | Download / arXiv / `id` | `id` 等宽小字 |

折叠卡高度（自定范围，见设计系统 §5）：**舒适档 160–200px、紧凑档 120–150px**，分别保证一屏约
4–5 / 6–7 张。硬约束：**最坏情形（超长标题）不得裁切底部操作行**，由标题严格两行截断吸收高度波动。
详情面板为全量字段 + 打分控件。

## 5. 实现映射（目标态 ↔ 现状）

> 这是「设计意图」与「代码现状」的对照表——**避免把规划当现状**。
> 现状判定依据：[需求与现状审阅](../product/review.md) §5。

| 能力 | 目标态 | M1 现状 | 计划 |
|------|--------|---------|------|
| 三栏布局 / 筛选 / 搜索 | ✅ | ✅ | — |
| 卡内「为什么推荐」 | ✅ | ⚠ 因 `hits_*` 存关键词、模板比对条目标题而**未渲染** | M1.x 修 |
| 卡内打分 + 权重变动角标 | ✅ | ⚠ 仅详情面板有按钮，无角标 | M1.x |
| 已打分 / 已下载状态位 | ✅ | ❌ | M1.x |
| 密度切换 / 主题跟随系统 | ✅ / ✅ | ⚠ 仅主题切换 | M1.x / M2 |
| 权重演化时间线 · 画像编辑 · 建议收件箱 | ✅ | ❌（`/profile` 只读） | M2/M3 |
| 归档库检索 / venue·年份统计 | ✅ | ❌（仅列表） | M3 |
| `⌘K` 命令面板 · `s` 收藏 · `n` 笔记 | ✅ | ❌ | M2+ |
| 洪峰日虚拟滚动 | ✅ | ⚠ 全量渲染 | M2 |

原型中：**已实现能力**按设计令牌正常呈现；**规划能力**一律加**虚线描边「规划中」徽标**并降低对比，
以示与现状可区分（见设计系统 §7 / §9.6）。

## 6. Anti-Slop 摘要（完整版见设计系统 §7）

**Never**：渐变滥用 · 玻璃拟态/backdrop-blur · 卡片圆角 >8px · emoji 当功能图标
（★/🧐 仅作语义字形）· 假头像/装饰插画 · Lorem 占位 · 暗色下重阴影做层级 · 第二品牌色 · 营销式 Hero。

**Prefer**：描边 + 亮度阶梯 + 左色条表达层级与状态；等宽承载一切数据；位置分层区分
「系统的判断」与「我的判断」。

## 7. 验证与审查

原型不是"看起来完整"，而是**经真实浏览器实测**的产物。验证手段与结论如下（完整版见[质量审查报告](critique.md)）：

| 验证手段 | 工具 | 结论 |
|---------|------|------|
| 静态阅读 + 数据核对 | 人工 + 与 `data/20260729.json`、`interests.md` 比对 | 128 篇真论文、5 条真兴趣条目（w=3），无 Lorem/假数据 |
| JS 语法 | `node --check` | 通过 |
| 零外部依赖 | 静态扫描 `@import`/`<link>`/`fetch`/`cdn` | 零命中 |
| **真实浏览器交互 + 控制台 + 截图** | **Edge 无头 + CDP**（`--headless=new --remote-debugging-port`） | 视图切换 / 主题 / 密度 / 数据集 / 筛选 / 键盘 `j/k`·`1–5` / 卡片点击 **全部生效**；console **零报错** |
| **WCAG AA 对比度实算** | CDP 取计算样式后计算对比度 | 三级文本 暗 **5.87/5.40:1**、亮 **5.72/5.14:1**；主按钮白字 **5.17:1**——全部 ≥ 4.5:1 |

> **一条值得记录的经验**：首版原型 `bindControls()` 函数定义完整却**漏掉启动调用**，导致约 16 个控件静默失效——静态阅读与 DOM 桩都未发现，最终由**无头浏览器实测**捕获。故本流程将"无头浏览器实测"列为原型交付的**强制关卡**。
