# Paper-Glean（摘星 StarDigest）Web 应用 · 设计需求摘要

> 用途：高保真 UI 原型设计（纯前端静态演示）的输入契约。
> 来源：全部字段/交互均取自真实实现（`glean/web/routes.py`、`glean/web/models.py`、`glean/templates/*`、`glean_static/*`、`glean/config.py`、`data/20260729.json`、`plan.md` §2/§3/§5/§7、`docs/product/*`、`docs/user-guide/web-app.md`）。
> 设计方向（用户已拍板，不再更改）：**学术专业 · 三栏工作台**；高信息密度、中性克制配色、键盘驱动、默认暗色可切换。

---

## 1. 五要素

| 维度 | 结论 |
|------|------|
| **场景（Surface）** | **本地 Web 工作台**（desktop-first，三栏布局）。非落地页、非营销页；是「每天要用、边看边打分」的生产力工具界面。三个视图：Digest 流（主）、兴趣画像、归档库。跨端仅需响应式降级（移动端可用即可，非重点）。 |
| **受众（Audience）** | **单用户 = 仓库所有者**，一名计算机科学研究人员（画像明确指向：分布式共识/BFT、事务隔离、形式化方法 TLA+/模型检测，以及 LLM×形式化交叉）。技术素养极高，熟键盘快捷键、看得懂 arXiv ID 与 `cs.DC` 类别码、会用 Git/Obsidian。**日常高频使用**（晨间浏览打分是固定仪式），因此效率与信息密度优先级远高于视觉新奇感。 |
| **调性（Tone）** | **学术专业、中性克制、工具理性**。参考方向：接近 Tech Utility（等宽字体承载 ID/得分/权重等数据、数据密集、克制的状态色）叠加 Modern Minimal 的留白与秩序感。**反对**：营销式大标题、高饱和渐变、拟物、装饰性插画。颜色为**语义化状态色**而非装饰：★（兴趣/黄/amber）、🧐（探索/蓝/blue）、其余（中性灰）。默认暗色，可切亮色。 |
| **品牌上下文（Brand Context）** | **全新品牌，无既有 VI**。现有实现即事实品牌线索：主色 `#3b82f6`（primary blue）、辅色 `#64748b`（slate）、Logo 文字「Paper-Glean」、现有技术栈 Tailwind 灰度体系（gray-50/900）。原型应延续这条蓝-中性灰基调，不引入第二个品牌色。命名体系（★/🧐 双通道、🎯命中、权重 w=N）是**产品的核心语义资产**，必须在视觉上形成固定记忆点。 |
| **规模（Scale）** | 3 个页面 + 1 个可折叠部件。**Digest 流为绝对重心**：三栏（左日期/筛选 · 中卡片流 · 右详情面板）；卡片组件需覆盖 7 种 UI 状态；列表量级 100~300 篇/日（见 §6）。画像页 = 条目卡片（2 列网格）+ 权重条 + （规划）演化时间线。归档页 = 数据表格。需响应式（lg 以下收起右栏）。交互复杂度：中等（键盘导航、即时打分反馈、筛选联动、暗色切换、密度切换）。 |

## 2. 关键页面清单（现有 3 页）

| 页面 | 路由 | 职责（一句话） |
|------|------|----------------|
| **Digest 流** | `/digest` | 每日论文的**主工作台**：按日期/类别/命中类型筛选卡片流，逐张浏览、打分、下载，右栏看详情与「为什么推荐」。 |
| **兴趣画像** | `/profile` | 把 `interests.md` 可视化为可读画像：★兴趣点 / 🧐扩展点两组条目，展示关键词、权重、来源（规划：权重演化时间线 + 待采纳建议收件箱）。 |
| **归档库** | `/archive` | 展示已下载 PDF（按修改时间倒序，最多 100 条），供快速定位与打开本地文件。 |

**公共外壳**：顶部导航（Logo + Digest/Profile/Archive + 暗色切换按钮），移动端降级为底部/顶部三 Tab。规划中的 `⌘K` 命令面板与 `🌙` 开关位于顶栏（IA 图中已体现）。

## 3. 核心用户任务流与现状摩擦点

### S-A 晨间浏览打分（核心场景）
`打开当天 digest → 快速扫读候选 → 逐篇判断兴趣度 → 打分调整画像 → 挑出要读的下载`
- 真实路径：选日期 → （默认已开 ★/🧐 命中，多数日子只看命中项）→ `j/k` 翻卡 → `1-5` 打 ★ / `Shift+1-5` 打 🧐。
- **现状摩擦点**：
  1. **打分无可见回执**——`hx-swap="none"`，卡片不显示「我打过的分」，也不显示权重变动提示（plan.md §5.2 要求的「分布式计算与共识 3→4」角标**未实现**）。
  2. **已打分/已读无法区分**——重进页面看不出哪些已评过，可能重复打分。
  3. **键盘选中态弱**——`[data-paper-id].selected` 只用 `ring`（且此 CSS 写法无效，见 §8），焦点感不足。
  4. **未命中项（其余）默认隐藏**——想「扫一眼全部」需手动勾选 `Other`，无「一键全部/仅命中」快捷态。
  5. **详情面板与卡片重复**——打分区在右栏，键盘打分作用于「中栏选中卡片」，两处状态不同步。

### S-B 画像维护
`查看当前兴趣条目与权重 → 发现漂移/遗漏 → 增删改条目与关键词 → 影响次日推荐`
- **现状摩擦点**：`/profile` 目前**纯只读**——无新增/编辑/删除，无权重滑块，无来源编辑，无演化时间线，无「建议新增条目」收件箱。用户仍须回头手改 `interests.md`。这是规划（plan.md §5.1）与实现之间最大的缺口。

### S-C 下载归档
`在卡片/详情上点下载 → 按命名规则落盘 → 在归档库确认`
- **现状摩擦点**：
  1. **下载无任何反馈**——`hx-post` + `swap:none`，成功/失败/进度均无提示，用户不知是否落盘。
  2. **无「已下载」标记**——卡片不知道这篇是否已在库，可能重复下载。
  3. **归档页缺搜索**——`web-app.md` 声称支持按文件名搜索，但 `archive.html` 未实现；仅列表 + 打开。
  4. **归档来源不一致**：实现读 `ARXIV_DIR`（默认 `~/papers`，可配环境变量），文档写 `arXiv/` 仓库目录——原型应按「本地 PDF 库」泛化处理，不要硬编码展示仓库内路径。

## 4. 内容模型：一张推荐卡片必须承载什么

一张折叠态卡片（Digest 中栏）的**必含信息**（依 `partials/paper_card.html` 真实字段）：

| 区块 | 字段 | 说明 / 约束 |
|------|------|-------------|
| 主标题 | `title` | 可点击跳 `abs_url`（新标签）。**最多 2 行**，超出省略。 |
| 类别徽标 | `primary` | 单枚，如 `cs.DC`；等宽小号。 |
| 命中徽标 | `hits_star` / `hits_expand` | ★ 徽标显示 `score_star`、🧐 徽标显示 `score_expand`；无命中则不渲染。`title` 悬浮提示命中条目名。 |
| 作者 | `authors` | **最多显示 4 位**，超出加 ` et al.`，单行省略。 |
| 摘要节选 | `abstract[:280]` | **最多 2 行**（`line-clamp-2`），约 280 字符截断。 |
| 为什么推荐 | 命中条目名 + `(w=权重)` | 仅当有命中时显示；逐个列出命中兴趣条目标题与其当前权重。**这是产品的灵魂，不可省略。** |
| 操作行 | Download 按钮 / arXiv 链接 / `id` | 底部分隔线之上；`id` 为等宽小字（如 `2607.25979`）。 |
| （规划增强） | agent 中文理由、🎯高亮命中词、我打的分、已下载标记 | plan.md §5.2 要求，实现尚未落地——原型可作为「目标态」体现。 |

**总长限制**：折叠卡片应控制在一屏可见 **4–6 张**（约 **4–5 行文本线**）内，保证高信息密度与快速扫读。
> *像素高度区间已在设计阶段修订：以 [设计系统 §5](design-system.md) 为准（comfortable 160–200px / compact 120–150px）；本处原 130–180px 为需求阶段估算，现已被其取代。*

详情面板（右栏）为**全量**：完整标题、全作者、`categories` 全部、★/🧐 得分、全文摘要、逐条命中清单、Open PDF / arXiv / Download、★1-5 与 🧐1-5 打分控件。

**数据量级（实测）**：`data/20260729.json` 单日 **128 篇**；`DEFAULT_CAP=100`/类别；`cs.LG` 洪峰日可**数百篇**。见 §6 性能约束。

## 5. 交互契约

### 5.1 键盘映射（`glean_static/js/app.js` 真实绑定 + plan.md 目标）
| 键 | 行为 | 现状 |
|----|------|------|
| `j` / `↓` | 选中下一张卡片（滚动居中 + 加载右栏详情） | ✅ 已实现 |
| `k` / `↑` | 选中上一张卡片 | ✅ 已实现 |
| `1`–`5` | 对**当前选中卡**打 ★（兴趣度，1-5） | ✅ 已实现 |
| `Shift+1`–`5` | 对**当前选中卡**打 🧐（好奇度，1-5） | ✅ 已实现 |
| `d` | 下载当前选中卡的 PDF | ✅ 已实现（但无反馈） |
| `o` | 新标签打开 arXiv 摘要页 | ✅ 已实现 |
| `/` | 聚焦搜索框 | ✅ 已实现 |
| `Escape` | 输入框内失焦 | ✅（隐式） |
| `s` 收藏 / `n` 记笔记 / `⌘K` 命令面板 | 规划，未实现 | ⬜ plan.md §5.2 |

**契约要求（原型需体现）**：所有键盘操作只作用于**当前选中卡**；当焦点在 `INPUT/TEXTAREA/SELECT` 时，除 `Escape` 外**不拦截按键**；`j/k` 到边界时**钳制**（不循环）；选中项须有**清晰可辨的选中视觉**（当前实现的 `ring` CSS 无效，原型必须给出真实可见的选中态）。

### 5.2 打分即生效的反馈形式（目标态）
- 无二次确认、无弹窗（plan.md §5.2）。
- 打分后卡片角标即时更新：显示「条目名 旧权重→新权重」（如 `分布式计算与共识 3→4`）。
- 卡片自身落一个「我打的 ★N / 🧐N」状态位，与命中徽标区分开（命中=系统算的，评分=我给的）。
- 反馈规则（真实逻辑）：评分 ≥4 → 命中条目权重 **+1**；≤2 → **-1**；写入 `feedback.jsonl`（append-only，可回放撤销）。

### 5.3 暗色模式
- **默认暗色**（`darkMode = localStorage.getItem('darkMode') !== 'false'`，无存储即暗色）；顶栏按钮切换；跟随系统为规划项。
- 切换需平滑过渡（现有 CSS 对 bg/text 过渡 0.2s）。

### 5.4 阅读密度切换
- 规划中的「舒适 / 紧凑」两档。紧凑档压缩卡片垂直间距与摘要行数（如从 2 行降为 1 行），提升单屏可见卡数。

## 6. 必须覆盖的 UI 状态

| # | 状态 | 触发条件 | 原型须呈现 |
|---|------|----------|-----------|
| 1 | **默认** | 有数据、默认筛选 | 卡片流 + 首张或未选中的右栏空态 |
| 2 | **筛选为空** | 搜索/类别/命中组合无结果 | 空态卡：`No papers found matching your filters.` + 引导「清空筛选」 |
| 3 | **无数据日** | `list_available_days()` 为空 | 日期下拉空、论文列表空、明确「暂无数据，请先运行抓取」引导 |
| 4 | **未命中（其余）** | `show_other` 默认关 | 这类卡片默认不展示；开启后需与命中卡**视觉可区分**（无 ★/🧐 徽标，弱化） |
| 5 | **已打分** | 用户已给过评分 | 卡片显示「我打的 ★N/🧐N」；再次打分**覆盖**而非叠加；重进页面应保留（需持久化） |
| 6 | **已下载** | 该 PDF 已在本地库 | 卡片/按钮显示「已下载」态（禁用或改文案）+ 加入归档库 |
| 7 | **详情面板空态** | 未选中任何卡 / 移动端收起 | `Select a paper to view details` 占位 |
| 8 | **详情面板有值** | 选中某卡 | 全量字段 + 打分控件 + 操作按钮 |
| 9 | **洪峰日性能态** | cs.LG 数百篇/日 | 卡片流需虚拟滚动/懒加载；摘要懒展开；筛选/翻页不卡顿（见下） |
| 10 | （建议）**加载中 / 提交中** | HTMX 请求在途 | 骨架或 `htmx-request` 半透明态 |

**性能约束**：单日可达数百篇（`DEFAULT_CAP=100`/类别 × 9 类别；实测单日 128 篇）。列表渲染必须**虚拟滚动**，卡片懒挂载；`⌘K`/搜索为前端即时过滤。原型可静态演示，但**信息架构与分页/懒加载策略必须能支撑该量级**。

## 7. 约束与非目标

### 原型约束（硬）
1. **纯前端静态演示**：无后端、无真实网络请求。所有交互用静态数据 + 前端状态模拟。
2. **字段可对应真实实现**：卡片/详情出现的每个字段（`title/authors/primary/categories/score_star/score_expand/hits_star/hits_expand/w/abs_url/pdf_url/id`）必须来自真实 schema（见 §4 与 `data-schema.md`），不得杜撰字段。
3. **可解释性不可退化**：任何卡片必须能回答「为什么推荐」——命中条目 + 权重得分；不得出现无理由的「你可能喜欢」。
4. **★/🧐 双通道始终分离**：兴趣点只产 ★ 候选、扩展点只产 🧐 候选，视觉上两种徽标体系不可混同。
5. **数据可信度**：原型内示例数据应贴近真实（用 `data/20260729.json` 的论文、`interests.md` 的真实条目与权重），避免「Lorem ipsum」式占位。

### 明确不做（Non-Goals，plan.md §7 + `docs/product/non-goals.md`）
- ❌ 多用户 / 社交 / 评论 / 协作共享
- ❌ 云托管与账号体系（登录/注册）——违背本地优先
- ❌ 通用引文图谱探索（外链 Connected Papers 等即可）
- ❌ 通用 AI 文献问答 / 系统综述工具（外链 Elicit/Undermind；仅库内 RAG 属远期）
- ❌ 改变 PDF 落盘命名规则与 venue 目录结构
- ❌ 自建爬虫绕过官方 API

## 8. 开放问题（需 design-system-expert / prototype-builder 决策的取舍点）

1. **双通道色彩体系**：★（黄/amber）与 🧐（蓝/blue）如何在**默认暗色**下同时保持区分度与克制感？现有实现用 `#3b82f6` 主蓝 + amber，需确认暗色下的对比与语义不冲突。
2. **「命中得分」vs「我的评分」视觉分层**：两者都是 0/1–5 的星/条计数，极易混淆。需建立明确的视觉语言（如：命中=实心徽标+数值；我的评分=可点的分段控件）。
3. **高密度与可读性的平衡点**：目标是「一屏 4–6 张卡」，但每张卡要装 8+ 字段。需要在字号阶梯、行高、摘要行数上给出明确 token，避免变成「看不清的表格」。
4. **选中态与键盘焦点的可及性**：当前 `[data-paper-id].selected { ring: ... }` 是**无效 CSS**（`ring` 不是 CSS 属性），实际选中样式未生效。原型必须给出真实可见、且在暗/亮色下都达对比标准的选中态。
5. **已打分/已下载的持久化表达**：静态原型如何表达「跨会话保留」的状态（localStorage 模拟？预置多张不同状态卡片？）——建议在同一视图内并置展示 5 种状态卡，供评审一次性看全。
6. **详情面板的落位**：桌面三栏（右栏常驻）vs 窄屏（抽屉/弹层）。响应式断点与右栏内容在小屏的降级方式需定。
7. **画像页的「目标态 vs 现状」边界**：`/profile` 现为只读，规划含表单编辑 + 权重滑块 + 时间线。原型应做到哪一层？建议至少呈现「权重可调 + 时间线」的目标态，并标注哪些属 M2+。
8. **规划功能的呈现策略**：`⌘K`、密度切换、收藏/笔记、agent 中文理由等尚未实现。原型可作「目标态蓝图」收录，但需与「已实现」在视觉/注释上**可区分**，避免误导为现状能力。
9. **归档页的搜索与统计**：文档声称有搜索但实现没有；规划含 venue/年份统计面板。原型按「现状 + 轻量增强」还是「完整 M3 目标态」呈现，需定调。
10. **示例数据规模**：为演示虚拟滚动/空态/洪峰，建议同时提供「正常日（~30 篇命中）」与「洪峰日（300+ 篇）」两组可切换静态数据集。
