# 非目标边界

> 明确不做的事项及理由

## Won't Do 清单

| 不做什么 | 理由 |
|---------|------|
| **多用户 / 社交 / 评论** | 单人工作台定位；社交讨论外链 alphaXiv 即可 |
| **云托管与账号体系** | 违背本地优先与数据主权原则 |
| **通用引文图谱探索** | Connected Papers / Litmaps / ResearchRabbit 已做得足够好，外链之 |
| **通用 AI 文献问答 / 系统综述工具** | Elicit / Undermind 已覆盖，按需外用；本应用只做库内 RAG（远期） |
| **改变 PDF 落盘命名规则与 venue 目录结构** | 这是本仓库最重要的既有资产与不可替代特色 |
| **自建爬虫绕过官方 API** | 只用官方 API/RSS 并遵守配额礼仪 |

## 为什么明确非目标很重要

### 防止范围蔓延

每个「不做」的决定都释放开发资源，让我们能把 M1-M4 的有限精力集中在真正创造差异化价值的功能上。

### 维护产品定位

Paper-Glean 的核心价值是**个人、本地、可审计**。任何偏离这三点的功能都会稀释产品定位。

### 利用现有工具

在以下领域，现有工具已足够好，无需自研：

| 需求 | 推荐外链 | 理由 |
|------|----------|------|
| 引文图谱探索 | [Connected Papers](https://www.connectedpapers.com/) | 可视化体验优秀 |
| 文献综述 | [Elicit](https://elicit.org/) | AI 综述能力领先 |
| 社交讨论 | [alphaXiv](https://alphaxiv.org/) | 论文评论区活跃 |
| 通用搜索 | [Semantic Scholar](https://www.semanticscholar.org/) | 引文数据丰富 |

### 决策框架

当考虑新功能时，用以下问题过滤：

1. 是否违背本地优先原则？→ 不做
2. 是否有成熟的现成工具？→ 外链，不自研
3. 是否使 CLI/Obsidian 工作流失效？→ 不做
4. 是否无法解释推荐理由？→ 不做
5. 是否改变 PDF 命名/目录结构？→ 不做
