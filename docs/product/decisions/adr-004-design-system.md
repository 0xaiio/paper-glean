# ADR-004: 为什么选用 Linear 设计系统基因（而非 Vercel / Raycast）

> 状态：已接受
> 日期：2026-09-13

## 背景

`plan.md` §5 描述了 Web 界面的目标形态，M1 实现后需要一次**设计定稿**：为三栏工作台
（Digest 流 / 兴趣画像 / 归档库）确立统一的设计语言与令牌，使后续开发有据可依。

本项目的界面有四个硬性特征：
1. **高信息密度**——一张卡要装 8+ 字段，一屏要放 4–6 张；
2. **键盘驱动**——`j/k/1-5/d/o//` 是日常操作方式；
3. **长时阅读**——晨间固定使用，暗色为主；
4. **双通道语义色**——★ amber 与 🧐 blue 必须互不混同。

## 考虑的方案

| 方案 | 设计系统 | 特征 | 与四特征的匹配 |
|------|---------|------|---------------|
| **A（选定）** | **Linear** | 暗色优先、高密度、键盘原生（`⌘K` 文化）、1px 描边替代阴影、12–14px 紧凑排版 | ★★★★★ 四特征一一对应 |
| B | **Vercel** | 近单色极简、Geist 字体、锐利直角、浅色为主 | ★★★★☆ 气质最纯，但浅色优先、暗色层级线索弱 |
| C | **Raycast** | 命令面板式、键盘优先、深色磨砂 | ★★★☆☆ 形态偏「启动器」，撑不起三栏 + 长摘要，且毛玻璃与 Anti-Slop 冲突 |

## 决策

采用 **方案 A：Linear 设计系统的「基因」**——移植其**结构、密度、排版与层级语言**，
但**不引入 Linear 的品牌色**（indigo/purple），沿用本仓库既有主色 `#3b82f6`。

## 理由

1. **密度与可读性的平衡**：Linear 以 13px 正文 + 紧凑行高 + 1px 描边划分层级，
   恰是「一屏 4–6 张卡且不糊」所需；
2. **键盘原生**：本项目的键盘契约（`j/k`、单键操作）与 Linear 的工具基因同源，
   选中态/焦点环规范可直接借鉴；
3. **长时阅读友好**：明暗双主题均为长时间使用优化（正文对比约 8:1，而非纯黑纯白对撞）；
4. **语义色克制**：Linear 是「少量语义色 + 大量中性色」的典范，能承载 ★/🧐 双通道而不抢戏；
5. **延续既有资产**：不引入第二品牌色，与 M1 已实现的蓝-灰基调平滑衔接。

## 后果

### 正面

- 三栏工作台获得统一的密度、排版与层级语言，令牌化（CSS 变量）后可直接被实现消费
- 双通道语义色与「命中得分 vs 我的评分」的视觉分层有明确规范（见 [界面设计规范](../../design/index.md) §3.2）
- 设计系统与「本地优先、可解释」的产品原则气质一致：工具理性、拒绝装饰

### 负面

- Linear 的「暗色优先」意味着浅色主题需要额外校色（已在令牌表给出 Light 全套）
- 高密度对排版精度要求高，字号/行高的容错空间小
- 属「借鉴基因」而非「采用完整组件库」，组件需自行实现（但本项目规模小，成本可接受）
