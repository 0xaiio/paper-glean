# ADR-003: 本地优先与数据主权

> 状态：已接受
> 日期：2026-07-29

## 背景

在规划 Paper-Glean 时，一个根本问题是：数据应该存储在哪里？这不仅是技术选择，更是产品哲学的体现。

## 决策

**数据必须完全本地存储，拒绝任何云端依赖。**

## 理由

### 1. 数据主权

研究者的阅读历史、兴趣演化、评分记录是高度个人化的数据。这些数据：
- 可能包含未发表的研究方向
- 反映了个人学术品味的发展轨迹
- 具有长期价值（可回溯数年）

将这类数据托管到第三方服务，存在：
- 隐私泄露风险
- 服务关停导致数据丢失
- 无法自由导出/迁移

### 2. Git 作为时间机器

文件存储 + Git 版本化提供了数据库无法比拟的优势：

```bash
# 查看兴趣画像的历史变化
git log -p interests.md

# 回溯到三个月前的画像状态
git checkout $(git rev-list -n 1 --before="3 months ago" HEAD) -- interests.md

# 比较两个时间点的权重变化
git diff HEAD~30 interests.md
```

### 3. 离线可用

研究者常在以下场景使用：
- 飞机上/高铁上（无网络）
- 会议现场（网络不稳定）
- 实验室（内网环境）

本地优先确保这些场景下系统完全可用。

### 4. 随时退出

用户应该能随时：
- 不带任何障碍地导出全部数据
- 在不通知任何服务的情况下停止使用
- 将数据迁移到其他工具

文件格式（Markdown + JSON）确保了这一点。

## 实施约束

基于本决策，以下功能明确不做：

- ❌ 用户账号系统
- ❌ 云端同步
- ❌ 社交功能（分享、关注、评论）
- ❌ 第三方登录
- ❌ 使用任何需要 API key 的专属云服务

## 例外

以下外部调用是允许的，因为它们不存储用户数据：

- ✅ arXiv API（只读，获取公开论文）
- ✅ Semantic Scholar API（可选，补充引文数据）
- ✅ LLM API（可选，生成推荐理由，输入为公开论文摘要）
