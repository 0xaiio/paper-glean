## 📌 TL;DR（执行摘要）

- **核心目标**：回答 paper-glean 是「继续当作者自用的个人工具」，还是「演进为面向大众的开源产品」——并给出可执行、可止损的路线。
- **关键决策**：**推荐「路径 C 精炼版」——单人精品主干 + 闭环优先 + 低成本分发杠杆**。明确**否决**「开源产品化」作主线，把「精品自用」作下限保底。
- **最重要的一次次序修正**：**多源接入后置**。原规划 M2 = 多源 + 嵌入推荐；但产品唯一不可替代的价值是「反馈→画像演化→更准推荐」闭环，而该闭环**当前零使用**（`feedback.jsonl` = 0 条、`interests.md` 的 weight 恒为 3）。**在未被验证的核心上盖楼是当前最大的战略风险**，故插入 M1.x 先修闭环。
- **定位取舍**：**不做大众工具，做小众精准楔子**。70–80% 的「实用性多数」会被 Scholar Inbox 的零维护拿走；paper-glean 只锁定 **20–30% 的主权派与可审计派**，用 H1（画像可审计）+ H3（本地规则归档）的**结构性护城河**换取精准与忠诚。
- **护城河复检结论**：2026 下半年赛道显著升温（新增 9 个玩家），但 **H1+H3 组合仍无替代**——护城河经受住了 6 个月考验；★/🧐 双通道**全网未见第二家**，且被竞品自承认的缺陷（Scholar Inbox「不支持区分多个研究兴趣」）反向验证。
- **下一步**：执行 M1.x「最小闭环」（**≈3 人周**，7 项），随后给 **4 周数据积累窗（不考核 KPI）**，再评估 **WER（每周有效打分次数）≥3/周**。WER 不活，一切扩张免谈。
- **M2 闸门判据**（v2 新增）：**R-01 ∧ R-04 ∧ R-16 三项同时满足**——「为什么推荐」渲染率 100% **且** 画像出现 ≠3 权重 **且** 反馈原子写入落实。**闭环不活，不开多源。**

## 1.2 四条设计原则（功能取舍的唯一仲裁标准）

| # | 原则 | 落点 |
|---|------|------|
| P① | 本地优先 local-first | 数据全在仓库内；无数据库、无账号 |
| P② | Markdown/JSON 为唯一事实源 | Web 只是视图层，文件可手工编辑 |
| P③ | CLI 永远是 fallback | `core.py` 纯函数被 CLI 与 Web 共用 |
| P④ | **可解释推荐** | 每条推荐须回答「为什么推荐给我」——拒绝黑盒 |

## 1.3 已知缺口（本次战略的直接输入）

**A. M1 仅为设计目标的子集**（`docs/product/review.md` §5 已核实），缺 7 项交互：

卡内打分 + 权重变动角标｜已打分/已下载状态位｜`⌘K` 命令面板｜`s` 收藏 / `n` 笔记｜权重演化时间线｜「建议新增条目」收件箱｜归档库检索 + venue/年份统计｜可视化面板｜洪峰日虚拟滚动。

**B. 1 个实现缺陷，且直接违反第 4 条原则**（`glean/templates/partials/paper_card.html`）：

> 模板用 `interest.title in paper.hits_star` 判断是否显示「Why recommended」，但 `hits_star` 存的是**命中的关键词**而非**条目标题** → **该区块永不渲染**。

**战略含义**：一个以「可解释推荐」为灵魂的产品，其核心解释区块**实际为空**。这是**定位与实现之间最大的自相矛盾**，必须在任何扩功能之前修复。【判断】

**C. 工程债**：`filelock` 在 `pyproject.toml` 声明但从未 import；无原子写入（ADR-002 描述的是设计意图而非现状）→ 存在反馈数据损坏风险。

## 2.3 时效性核查：survey.md 两处「待验证」收口

`survey.md` 完稿于 2026-07-29，自述结论有效期约 6 个月，并遗留两处「待验证」。本轮核查结果：

| 待验证项 | 核查结论 | 证据 | 对战略的影响 |
|---------|---------|------|-------------|
| (a) Scholar Inbox 是否已开放**画像导出** | **高置信度否定**（可收口） | 官方导出能力仅「Smart Collections → 导出 BibTeX」；其「数据公开」是**匿名聚合发布研究数据集**（774k 匿名评分，仓库 `avg-dev/scholar_inbox_datasets`），≠ 用户可导出自己的画像 | H1 护城河**未被侵蚀**，反而被强化 |
| (b) Zotero 7/8 + Attanger 能否**精确还原** `arXiv<年份> <id><版本> <去标点标题>.pdf` | **部分前进，但仍未确证** | Zotero 8 官方重命名字段表已含 `archiveID`/`versionNumber`/`repository` 并支持正则替换（`replaceFrom`/`replaceTo`）；但本仓库去标点算法是 `core.py` 自定义实现，逐字一致无证据；且「venue 目录即分类」范式冲突未变 | H3 护城河**经受住 6 个月考验**，但需实测验证（见假设 C-02） |

残留风险：Scholar Inbox 登录态设置页若有导出入口，公开检索不可见 → 标【待验证·低概率】，已登记为假设 C-03。

## 2.6 借鉴清单

**应当借鉴（5 条）**

1. Scholar Inbox 的 **active learning 冷启动**（引导先标注 20–50 篇 bootstrap）——降低空画像门槛（直接对应当前「weight 恒为 3、feedback 为 0」的困境）。
2. `zotero-arxiv-daily` 的 **「用已有文献库当隐式画像」**——用于「库内已有相关论文」提示。
3. `preprint-recommender` 的 **GitHub Actions 零成本托管 + `offsetDays` 处理预印本索引延迟**。
4. **arXivSub 的 MCP server / agent skill 分发**——把 paper-glean 暴露给 Claude/Cursor 调用，低成本获客渠道。
5. SciFACE 的 **facet 分解（Background/Method）**——强化「为什么推荐」的多维解释。

**不应借鉴（5 条）**

1. 云端训练黑盒模型（违背 P④/H1/H2）
2. 「整个文献库=画像、不可显式编辑」（违背 H1）
3. venue 批量灌库军备竞赛（成本高、非差异化）
4. 订阅付费 newsletter（违背免费开源 + 本地）
5. 自动扒 Google Scholar/GitHub 画像（隐私与可控性差）

## 4.3 关键判断：「可审计画像」与「本地主权」的真实感知权重

这是本次用户研究**最重要的一节**，结论对战略取舍具有决定性。

**① 可审计画像：刚需还是洁癖？**

- 【事实】剑桥 Katy Jordan 等研究：研究者普遍把 Google Scholar 称「total black box / algorithmic magic」，**但照样用**，补偿方式仅「多用几个平台」。
- 【事实】对黑盒的学术批评真实存在（Matthew 效应、主张「推荐不应是黑盒」），但**集中于研究推荐算法的小众学者**。
- **【推断】多数（约 80%+）研究者视可审计为「锦上添花 / 洁癖」；约 10–15%（形式化/PL/系统方向、读代码、研究推荐算法者）是真刚需**——**而后者恰是早期采纳者与口碑源**。

**② 本地主权：谁是刚需？**

- 【事实】高校合规指南（Penn / Georgia Tech / Trinity / CAUT）：涉及**人类受试者 / FERPA / HIPAA / 国防 / 专利 / NDA 约束**的研究，把数据放未签约云 = 违规 → 合规敏感者「本机」是**硬约束**，约 5–10%。
- 【事实】另有强烈「创伤记忆」人群：Mendeley 卖 Elsevier 引发 #mendelete（数据库被锁死）；Google Reader 2013 关停请愿破 10 万签名、Feedly 48h 涨 50 万用户。这批人把本地主权当**价值观**，约 10–15%。
- **【诚实修正·关键】paper-glean 的「兴趣画像」敏感度远低于研究数据本身——「我喜欢哪些论文」通常不构成合规风险。因此本地主权对合规人群多是「顺带买账」，未必转化为本产品刚需；真正为它买单的是「创伤记忆 + 开源价值观」拥趸。**

**③ 反向证据：用户会为「更好推荐 + 零维护」放弃这两点吗？**

- 【事实】**Scholar Inbox：23k 注册 / 近 30 天 8k 活跃（35% 留存）/ 1,233 人评价「极正面」**，评分数据匿名化后公开发布、托管欧盟 → **直接证明：推荐够准 + 零维护时，大量研究者主动选托管，根本不问可审计/数据在哪。**
- **但**——其论文自己承认**最大抱怨是「不支持区分多个研究兴趣」**。**这恰是 paper-glean ★/🧐 严格分流的真实空档。**

**④ 两类用户占比【假设】**

| 类型 | 占比 | 特征 | 对两大主张的态度 |
|------|------|------|-----------------|
| **实用性多数** | **70–80%** | 要「准 + 省事 + 随手可得」 | 可审计 = 可有可无；本地主权 = 不关心 |
| **主权 / 可审计派** | **20–30%**（合规硬约束 ~5–10%、价值观型 ~10–15%） | 系统/形式化研究者、自托管拥趸、合规敏感者 | 可审计/主权 = 刚需或强偏好 |

> **核心结论（决定性）**：**两大主张不是大众卖点，而是「小众但高价值、高传播力」的定位楔子。按「大众工具」打，必输给 Scholar Inbox 的零维护；按「给主权派的可审计/自托管工作台」打，人群虽小但精准忠诚。**

## 4.4 采纳阻力与习惯化触发点

**前 5 大阻力**

| # | 阻力 | 证据 | 缓解思路 |
|---|------|------|---------|
| 1 | **要装 Python / 维护脚本** | arxiv-sanity 步骤繁琐且作者停更；「你不再是用户，而是系统管理员」 | Docker 一键镜像、托管 demo；已有 Windows 计划任务覆盖 |
| 2 | **注意力边际成本** | 用户已有 arXiv 邮件/RSS/多 alert，「再看一份日报」是**净负担** | **必须替换而非叠加**；输出极短（「今天只有 3 篇值得看」） |
| 3 | 习惯难改 / 切换成本 | HN local-first 讨论：主流用户「口头要隐私，很少为此付费或换工具」 | 从「顺手小动作」切入，不要求重构工作流 |
| 4 | 担心 arXiv 封号 | arXiv API 条款限 **1 请求/3 秒**、单连接，超限封禁；arxiv-sanity README 亦警告 | 内置限速与退避、明示合规边界 |
| 5 | 「免费也怕养不活/停服」 | arxiv-sanity 停更、Google Reader / Mendeley 前车之鉴 | **「纯本地文件 + 无服务依赖 = 停服免疫」应作卖点明说** |

**习惯化触发点（原话）**

> **触发点 = 接入一个已存在的每日仪式，且不增加任何新动作。**
> 具体即：**早上打开一个已被定时生成、只有 3–10 张卡片、可 1 键打分 + 1 键下载的本地页面**。
> **只要需要「先登录 / 先抓取 / 先配环境 / 再看 200 条」，就不成习惯。「零干预定时产出 + 极短消费动作」是唯一习惯化路径。**

# 第五部分：差异化定位

## 5.1 定位声明

**① 完整句式版**

> For **已有本地 PDF 库、以「可审计画像」为准绳的严谨研究者**，who **被筛选（triage）过载折磨、又不信任黑盒排序**，paper-glean is a **个人、本地优先、画像可审计的论文推荐与归档工作台**，that **解释每条推荐的理由、按你自己的规则落盘 PDF、数据永不旁落**。
> Unlike **Scholar Inbox / Zotero+插件 / arxiv-sanity**，we **把「纯文本可审计画像 + 规则化可审计反馈 + 本地 PDF 落盘」三者合一**——在 10 款横向对比中，H1+H3 两列同时 ✅ 的仍只有它。

**② 一句话版（README 首屏）**

> **画像可审计、按你的规则归档、数据永不出本机的每日论文工作台。**

**③ 反定位（我们不服务谁）——最关键的一节**

瑞思证据表明 70–80% 的「实用性多数」会被 Scholar Inbox 的零维护拿走。**明确取舍：不做大众工具，做小众楔子。**

| 不服务 | 理由 | 请改用 |
|--------|------|--------|
| 要「零维护、跨设备、开箱即用」的多数研究者 | 边际价值高但**采纳阻力最高**（装 Python、改习惯、注意力边际成本）；已被 Scholar Inbox 满足 | **Scholar Inbox / arXivSub** |
| 只要「少而准」、无个人库、无所谓画像透明的工业界工程师 | paper-glean 对他们是「**过重**」 | **Scholar Inbox / ArXiv Pulse**（公司可报销） |
| 生医 / 化学 / 非 CS 跨学科者 | 当前 9 个 arXiv cs/math 类别对其覆盖为**零**；本地主权对合规人群是「顺带买账」 | **PubMed / Connected Papers** |

## 5.4 差异化机会与护城河逻辑

| # | 机会 | 护城河性质 | 我们不付出的代价 | 验证方式 |
|---|------|-----------|----------------|---------|
| 1 | **H1 + H3 组合** | **结构性**（商业模式冲突）：SaaS 靠云侧数据与订阅变现，**结构性地不愿**给「画像可导出 + PDF 落到用户自己的目录规则」——那等于自毁留存 | 长期自维护 | Zotero8+Attanger 对命名规则的还原度实测（可脚本化） |
| 2 | **★/🧐 双通道严格分离** | **先发/工程壁垒为主（易被抄）**，需产品哲学支撑 | 维护两套画像语义与两条候选池 | A/B：🧐 通道带来的新条目转化率是否显著高于对照组 |
| 3 | **反馈→权重规则化可审计演化** | **结构性偏强**：黑盒 SaaS 的核心壁垒正是不透明，开放审计 = 主动放弃「神秘感/数据依赖」 | 规则朴素，效果大概率不如训练模型（须诚实披露） | 盲测对比规则版 vs Scholar Inbox 的命中满意度 |
| 4 | **与既有 300+ venue / 数千 PDF 库深度绑定** | **结构性且不可复制**：用户多年积累的个人资产，任何产品无法凭空获得 | 绑定本机、迁移成本高 | 全库扫描「你的库里已有该作者 N 篇」的命中率 |
| 5 | **LLM agent 可编程喂料 + CLI fallback** | **工程/先发壁垒（易被抄）** | LLM 成本与隐私 | 自然语言喂料后画像条目扩充的准确率 |

> **护城河要较真的地方**：机会 1/3/4 是**结构性壁垒**（竞品的商业模式或资产结构决定了它做不了），1/4/5 里易被抄的是 **2 与 5**。**战略上必须把重兵压在 1/3/4，而 2 只作「回归锁定」而非「护城河论证」。**

# 第六部分：战略发展规划

## 6.1 约束盘点（一切排期的边界）

| # | 约束 | 量化 | 对路线图的影响 |
|---|------|------|--------------|
| C1 | 资源 | 单人 + **巴士因子 1** | 每期只允许一条主线；禁止并行两条重线 |
| C2 | 人力预算 | 3–6 人周/期 | 每期必须标「本期不做」边界 |
| C3 | 现金成本 | ≈$0（DBLP/OpenAlex/S2 免费；LLM 轻量 ≈$0.46/月） | **瓶颈是人力不是钱** → 排序按「人周」而非「美元」 |
| C4 | 市场规模断层 | TAM 3–5×10⁶ / SAM 10⁴–10⁵ / SOM 1–10³（当前 =1） | 追大众 = 跨 2 个数量级的发行缺口，非功能能补 |
| C5 | 品类商业模式 | 免费主流；Elicit 估值仅 $100M；ResearchRabbit 被收购 | **不支持订阅制大众产品**；变现假设一律不成立 |
| C6 | 合规红线 | arXiv API **1 req/3s** | 抓取逻辑必须串行限速；多源各自限速 |
| C7 | 习惯化硬要求 | 「零干预定时产出 + 极短消费动作（3–10 卡 / 1 键打分 / 1 键下载）」 | 任何「先登录/先抓取/先配环境/看 200 条」都**不成习惯** |
| C8 | 现状缺口 | M1 = 设计目标子集：**7 项交互缺口 + 1 实现缺陷**（推荐理由永不渲染） | M1.x 的第一优先级清单 |

> **关键推论**：C3 + C4 + C5 三者叠加 → **「面向大众开源产品」在经济上不成立**。C6 + C7 是**设计约束**，决定「薄视图层 + 极简动作」是必然架构，不是偏好。

## 6.2 战略岔路决策框架（核心）

| 维度 | **路径 A** 精品自用 | **路径 B** 开源产品化 | **路径 C** 主干 + 分发杠杆（**推荐**） |
|------|-------------------|---------------------|-----------------------------------|
| **成立前提** | 只认「作者本人持续用」为成功 | 存在愿为「准+省事」迁移的 10⁴ 人 | 作者自用闭环先活；分发渠道低成本可插拔 |
| **收益** | 维护成本最低；护城河天然 | 触达 10⁴；社区反馈加速 | 拿到路径 B 的子集触达，**不重写架构**；保全护城河 |
| **代价（量化）** | 影响力上限 = 1 人；无外部校验 | **3–6 人周/期持续** + 社区运营；且多源/语义正是竞品在赢的战场 | 每期额外 0.5–2 人周做渠道；仍锁死单维护者 |
| **6–12 月后悔场景** | 「做得很深但只有我用」，动机枯竭停更（重演 arxiv-sanity 2018 停维） | 「追大众把架构拖重、多源疲于奔命、口碑没起量但维护债压垮单人」 | 「渠道搭好了但闭环没活，卡在 SOM=1」 |
| **退出成本** | 极低 | **高**（已为大众重构） | 中（渠道可拔，主干干净） |
| **翻盘条件** | 无（主动放弃扩张） | 外部强口碑 + 可见融资/团队接力 | 闭环验证成功（G6）后平滑加多源 |

### 推荐：路径 C 精炼版，配合路径 A 作保底；**否决路径 B 作主线**

**判据链**

1. **闭环是唯一不可替代价值，但它现在没活**（`feedback.jsonl` = 0、weight 全为 3）。任何扩张前必须先在 n=1 上证明它。→ 这一步让「多源」从 M2 顺延，**是对原规划与 survey.md「路径三混合」的次序修正**。
2. **护城河只在 H1+H3 结构性成立**。多源/语义/界面/部署是竞品投重兵的红海 → 当作主线 = **用人/周换必输战场**。
3. **分发层可用低成本杠杆**（MCP server、GH Actions 模板、Docker 一键）——足以拿到路径 B 的**部分触达**，且不背架构债。这是 C 优于纯 A 的增量。
4. **C4/C5 决定「大众」不可达**，故 C 的目标不是抢占份额，而是**精准楔子人群的传播**（可审计刚需 ≈10–15%、主权派 20–30%），即**小而忠诚**而非**大而泛**。
5. **为何不选纯 A**：放弃分发 = 放弃唯一可能的翻盘路径（≥100★ / ≥10 真实用户是数析给的升格门槛）。

## 6.3 优先级框架

**选用：护城河加权分 = 用户价值 × 护城河强度 × (1 / 人周)**，而非纯 RICE。

**理由**：本品类是「注意力赢家通吃 + 触达结构性封顶（C4）」，纯 RICE 的 **Reach 维度会系统性误导**——把「多源覆盖」这种大 Reach / 低护城河项排到前列，**恰是竞品在赢的地方**。护城河加权把 Confidence 替换为**护城河强度**，更贴合「单人项目必须靠防御性存活」的现实。

## 6.6 可量化目标

**北极星：WER（每周有效打分次数，去重论文数）**

| 节点 | 目标 | 性质 | 依据 |
|------|------|------|------|
| 3 个月 | **≥5/周（单用户）** + 累积 ≥4 周可调参数据 | 保守但必要 | 分母 = 1 用户；`feedback.jsonl` 现为 0 条，**前 4 周只能是数据积累期** |
| 6 个月 | **≥8/周（活跃均值）且 ≥10 名真实外部用户各自 ≥3/周** | 激进 | 从 1 用户到 10+ 外部用户是**产品化跳跃**，非自然增长 |
| 12 个月 | **≥15/周（活跃均值）且 ≥100★** | 激进但可达 | 距「被认可小工具」（≥500★）约 1 个数量级 |

**其余 7 个指标（均可本地计算，现有埋点足够）**

| 指标 | 取证方式（文件 · 字段） | 6 月目标 | 12 月目标 |
|------|----------------------|---------|----------|
| 打分覆盖率 | `feedback.jsonl` 去重 id 数 ÷ `data/*.json` 中 `hits_star∪hits_expand` 非空论文数 | ≥40% | ≥60% |
| 高分下载率 | `feedback.jsonl` 中 `rating≥4` 的 id 后续出现 download 事件的比例 | ≥50% | ≥65% |
| 画像演化速率 | `feedback.jsonl` 的 `weight_updates` 非空事件数 / 周 | ≥5/周 | ≥10/周 |
| 画像宽度 | `interests.md` 条目数 · 关键词数 | 条目 ≥8 / 词 ≥70 | 条目 ≥10（无长期零命中条目） |
| 命中率 | `(hits 非空论文数) ÷ (当日总论文数)`（`data/*.json`） | 稳定 ≥8% | ≥10%（当前 7.8%） |
| 推荐精确率 | `feedback` 中 `rating≥4` 去重 id ÷ 全部已打分去重 id | ≥30% | ≥35% |
| 连续活跃周 streak | 连续有 feedback 事件的自然周数 | ≥8 周 | ≥20 周 |

**负向指标（变坏信号）**

> **画像演化速率 = 0 的连续周数，阈值：连续 ≥3 周为 0 → 红线。**
> 理由：它是「反馈→推荐演化」闭环是否真运转的探针；长期为 0 说明用户只在「消费」而非「训练」产品，**H2 护城河名存实亡**。**当前值已 = 0（weight 恒为 3），即已处红色状态——这是最优先要解决的问题。**
>
> **次级红线**：命中率 < 5%（画像已与信源脱节）。

**起步条件（须写进目标）**：**第 1–4 周只做数据积累**。`feedback.jsonl` = 0 条 → WER / 覆盖 / 演化速率 / 精确率 / streak 全部「数据不足」，**这 4 周不得作为任何 KPI 的考核窗口**。

## 6.7 成本与投入估算

| 项目 | 成本 | 标注 |

| **M2 多源接入**（外部现金） | **≈$0**（DBLP 免费、OpenAlex polite pool 免费、S2 有 key 1 req/s；128 篇/日引文补全 ≈128 req ≈2 分钟） | 【事实】 |

**① 作者本人 / 决策者 —— 该不该继续投、投多少**

**② 潜在开源用户 —— 凭什么用你而不是 Scholar Inbox / preprint-recommender**

> 若你要「够准 + 零维护」→ **别用我，用 Scholar Inbox**（23k 注册、8k 月活），它更省事。若你是**已有本地 PDF 库、在意画像透明、要按自己规则归档、数据永不旁落**的严谨研究者 → **用我**。我是唯一「解释每条推荐 + 按你规则落盘 + 画像可导出、可手改、可审计」的每日工作台。差异化三合一：**纯文本可审计画像 + 规则化可审计反馈 + 本地 PDF 落盘**；★/🧐 严格分离「利用 vs 探索」全网未见第二家。代价直说：你要自己跑 Python、要常年维护——**我不是零维护工具，是把控制权还给你**。

**③ 学术同行 / 评审 —— 方法论价值与可引用点**

> ① **可审计推荐**：自然语言画像 + 规则化（±1）+ 权重可回溯演化，对照黑盒 SaaS 的可复现性空档（呼应 Sci-Surf arXiv 2608.11973「verbalized profile」+10.4% 的路线，但补上**可审计性**这一被忽视维度）。
> ② **探索-利用分离（★/🧐）**：把「利用已知」与「探索新知」表现为**两条严格分离的候选池**，是推荐系统在学术检索场景下罕见的显式框架，可作对照实验的自变量。
> ③ **本地主权工作台**：以「兴趣画像」为最小可审计单元、数据不出本机，可作为隐私敏感科研场景的参考设计。
